# AgenticFlow — Deployment

## Deployment Objective

The demo is intentionally simple:

```text
Next.js → Vercel
FastAPI + LangGraph → Render
Providers → Demo implementations
Storage → Demo storage
```

Production can progressively replace each demo component.

## Local Development

Frontend:

```bash
npm install
npm run dev
```

Backend:

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

## Vercel

Deploy the Next.js application to Vercel.

Example:

```env
NEXT_PUBLIC_DEMO_MODE=true
NEXT_PUBLIC_API_URL=https://your-python-service.example.com
```

Do not place private AI, search, registry, or service secrets in `NEXT_PUBLIC_*` variables.

## Render

Deploy the Python FastAPI service separately.

Start command:

```bash
uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

The Python/LangGraph runtime should not be forced into the standard Next.js Vercel deployment.

## Environment Strategy

### Demo

```env
DEMO_MODE=true
LLM_PROVIDER=demo
SEARCH_PROVIDER=demo
```

### Production

```env
DEMO_MODE=false
LLM_PROVIDER=<approved-provider>
SEARCH_PROVIDER=<approved-provider>
SUPABASE_URL=<production-url>
```

Real values must be stored in the hosting provider's secret/environment-variable system.

## Scaling Principle

Do not introduce Kafka, Kubernetes, Redis, Celery, or complex microservices merely for appearance.

Evaluate first:

- request volume
- concurrent agent runs
- latency
- reliability
- cost
- compliance
- data retention
- integration requirements

Then add infrastructure where it solves a measured problem.
